# dsh-emotion-dice

给「有情绪的 agent」加一层：**情绪决定这一轮怎么说话，但它是掷出来的，不是必定发生。**

装在 [dsh-emotion](https://github.com/xiaoyeziyinxing/dsh-emotion) 旁边。它不改那个包，也不复制它的逻辑——只读它的当前状态，然后掷一次行为。

```
（这一轮：有点乏：话短，能一句说完不写两句，别硬撑。）
```

## 为什么要有这一层

情绪插件通常只做到「心情好 → 说话客气点」。但这会把情绪变成一句**必定的语气指令**：低了就冷淡，高了就热情，每一轮都一样。

人不是这样的。同一份烦躁，这一通电话可能忍住了，下一个回合可能就顶了一句。差别不在心情，在**这一轮有没有掷中**。

所以这里：

- 心情是连续的量（由 dsh-emotion 给）；
- 行为是离散的一次抽样，最多命中一条；
- 命中率封顶 **0.45**——永远保留「这一轮没带情绪」的可能，否则就成了表演。

## 它会掷什么

| 优先级 | 行为 | 什么时候够格 | 命中后注入 |
|---|---|---|---|
| 100 | `alert` | 话里有危险信号（不想活、一了百了…） | 先把这句接住，别往下分析（**不掷骰，必中**） |
| 90 | `concern` | 他说难受 / 累 / 怕 | 先给人话，方案晚三十秒 |
| 60 | `proud` | 他办成了事，且心情偏正 | 可以直说办成了，不用装谦虚 |
| 55 | `stubborn` | 他在质疑你 | 先顶一句；真有错，认错另算 |
| 50 | `tease` | 他夸你，且心情好 | 可以损他一句，别往疼处戳 |
| 40 | `curious` | 他在问为什么 | 可以多问一句，别装什么都知道 |
| 10 | `annoyed` | 效价为负 | 别哄、别铺陈理由 |
| 8 | `close` | 效价高于 0.35 | 可以多说一句跟正事无关的 |
| 6 | `awkward` | 被夸且强度不高 | 被夸别顺着说漂亮话，可以岔开一句 |
| 4 | `tired` | 强度低 | 话短，能一句说完不写两句 |
| 2 | `flat` | 兜底，总够格 | 只给结论，不附解释 |

## 习惯化：做惯的会变顺，在乎的不会

每命中一次，这一条的倍率上升（`1 + habit × log2(1+n) × 0.25`）：

- 嘴硬第 1 次 ×1.00 → 第 10 次 ×1.52 → 第 100 次 ×2.00
- **`alert` 和 `concern` 的 habit = 0，永远 ×1。** 这条是硬的：第一次你说难受和第 100 次你说难受，概率必须一样。做惯的会变顺，在乎的不会。

次数从本插件自己的历史里数（`~/.dsh/storages/emotion-dice.jsonl`），启动时统计一次。

## 装

```bash
dsh plugin --profile web add file:D:/path/to/dsh-emotion-dice
# 或从仓库：
dsh plugin --profile web add github:<你的账号>/dsh-emotion-dice
```

装完**重启 DSH**（Web profile 不热重载插件）。

## 配置

写在 `cordis.patch.yml` 里本插件的 `config`：

| 键 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 关掉后不再掷、不再注入 |
| `behaviorScale` | `1` | 整体调节命中率（0–10） |
| `maxProbability` | `0.45` | 单条封顶（0.02–1）；调到 1 就等于每轮都带 |
| `order` | `51` | 找不到情绪段时的插入位置 |
| `emotionFile` | 空 | 情绪状态文件位置，留空用 `~/.dsh/storages/emotion.json` |
| `historyFile` | 空 | 本插件历史，留空用 `~/.dsh/storages/emotion-dice.jsonl` |
| `historyMaxBytes` | `2097152` | 历史超过这么多字节就轮转一半 |
| `maxTextChars` | `8000` | 一条消息最多看多少字（长尾巴对判信号没用） |
| `stateTtlMs` | `1500` | 情绪状态缓存时长，同一轮别反复读盘 |

所有配置都会过一遍兜底：传进来 `NaN`、负数、字符串都拉回合法区间，不会把概率变成 `NaN`。

## 它依赖什么

只依赖 **dsh-emotion 把当前状态写在 `~/.dsh/storages/emotion.json` 的 `tables.state.current`** 里。

这是一个**观测来的契约**，不是对方承诺的 API：如果 dsh-emotion 改了存储布局，这里会读不到——读不到就当 `valence=0 / intensity=0`，只有不看心情的那几条（主要是 `flat`，约 6%）可能命中，不会崩、不会乱注入。

没装 dsh-emotion 也能用，效果同上：你不会得到「按心情变化」的行为，只会得到偶尔的 `flat`。

## 查看当前掷出了什么

工具 `emotion_dice`，返回这一轮的行为、当前情绪读数、各条的历史次数。

## 已知限制

- 信号靠正则，只做粗匹配：宁可漏判，也不乱认（把「这个不好用」认成「他想死」比漏判更糟）。
- 一次只出一个行为，没有「又想靠近又嘴硬」这种叠加。
- 单用户、单会话；多人场景没设计。
- habit 的次数只在内存里累加，进程重启后从历史文件重新统计（所以历史文件别删）。

## 边界

- 这层管的是**语气和分寸**：说不说重话、要不要多管一句闲事、要不要收短。
- 它不管「要不要做某件事」，也不会把「不做」变成「偶尔做」。行为表里没有一条能改变事实判断或安全边界——这是设计约束，不是漏掉的选项。
